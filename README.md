# cd2-115-tidy

常驻 Web 服务，用来整理 **CloudDrive2** 挂载的 115 网盘图集目录：

1. **递归重命名** —— 每个含图片的目录各自从 `0001` 起编号（位数可配），保留目录结构
2. **清理** —— 删除目录里的非图片文件，以及因此变空的目录
3. **限速** —— 按云端 QPS 上限节流，避开 115 风控

## 为什么它不快（以及为什么不快是对的）

这个工具**故意做得很慢**。原因是实测数据：

| 事实 | 数值 |
| --- | --- |
| CD2 的 `RenameFiles` 批量接口 | **不会**合并云端调用，仍逐文件下发 |
| 单文件云端耗时 | 约 1.1 秒 |
| 客户端并发 | **完全无效** —— CD2 服务端全局串行 |
| 115 报给 CD2 的 QPS 上限 | 5.0 |
| CD2 给 115 的默认配置 | **0.9** |

所以吞吐量由 CD2 的 `maxQueriesPerSecond` 决定，与客户端并发无关。CD2 默认给 115 配 0.9 QPS 是有意为之的保守值 —— 实测在这个速率下 300+ 次改名**零失败、零风控**。

**9000 张图 ≈ 3 小时。这是当前配置下的物理上限。**

如果你执意加速，去 CloudDrive2 界面把 115 的 QPS 上限调高（115 自报可到 5.0），你能快 5 倍，但风控风险自负。本服务不代你改这个配置。

## 部署

### Unraid

**方法一：模板安装（推荐，点几下就行）**

在 Unraid 终端跑一次这条，把模板装进本地模板目录：

```bash
mkdir -p /boot/config/plugins/dockerMan/templates-user
curl -fsSL -o /boot/config/plugins/dockerMan/templates-user/my-cd2-115-tidy.xml \
  https://cdn.jsdelivr.net/gh/squallnk/cd2-115-tidy@main/unraid/cd2-115-tidy.xml
```

> 用的是 jsDelivr CDN（国内可达）。如果拉不到，可换回 GitHub 原始地址：
> `https://raw.githubusercontent.com/squallnk/cd2-115-tidy/main/unraid/cd2-115-tidy.xml`
> 或直接在 GitHub 网页上打开模板文件、复制内容、在 Unraid 上用记事本存成
> `/boot/config/plugins/dockerMan/templates-user/my-cd2-115-tidy.xml`。

> ⚠️ **更新模板时会遇到 CDN 缓存**：jsDelivr 对 `@main` 这类分支引用有缓存（可滞后数小时），
> 直接重下很可能拿到的还是旧版本 —— 而且不报错，只是新字段不生效。
> 想立刻拿到最新版，给 URL 加个时间戳绕开缓存：
>
> ```bash
> curl -fsSL -o /boot/config/plugins/dockerMan/templates-user/my-cd2-115-tidy.xml \
>   "https://cdn.jsdelivr.net/gh/squallnk/cd2-115-tidy@main/unraid/cd2-115-tidy.xml?t=$(date +%s)"
> ```
>
> 或者用具体 commit hash 替代 `@main`（例如 `@8bb1230`），hash 引用不走缓存。
> 验证是否拿到新版：`wc -c` 看字节数，以及 `grep Category` 看字段。

然后 **Docker 页面 → Add Container → Template 下拉选 `cd2-115-tidy`**，
只需填 **CD2 令牌** 一项，其余已预填，点 Apply 即可。

**方法二：Docker Compose Manager 插件**

1. 新建目录 `/mnt/user/appdata/cd2-115-tidy`，放入仓库里的 `docker-compose.yml`
2. 编辑它，填上 CD2 地址和令牌
3. `docker compose up -d`

**方法三：纯 docker run**

见下方。

装完统一打开 `http://<你的IP>:8380`

### docker run

```bash
docker run -d \
  --name cd2-115-tidy \
  --restart unless-stopped \
  -p 8380:8080 \
  -e CD2_URL=192.168.0.254:19798 \
  -e CD2_TOKEN=你的令牌 \
  -e ROOT_PATH=/115/4 \
  -e PAD=4 \
  -v /mnt/user/appdata/cd2-115-tidy/data:/data \
  ghcr.io/squallnk/cd2-115-tidy:latest
```

## 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `CD2_URL` | `127.0.0.1:19798` | CloudDrive2 gRPC 地址，`主机:端口`，**不要带协议前缀** |
| `CD2_TOKEN` | — | CD2 的 API 令牌。**必填** |
| `ROOT_PATH` | `/115/4` | 要整理的目标目录 |
| `PAD` | `4` | 编号位数，4 → `0001.jpg`。目录内图超过 10^PAD 张时自动加宽 |
| `SCAN_CONC` | `4` | 扫描（只读遍历）并发。不影响改名速度 |
| `WATCH_INTERVAL` | `7200` | 自动整理间隔（秒）。每 2 小时自动扫一次并改名；设 `0` 关闭 |
| `PREFIX_STRIP` | `^www[.]98T[.]la@` | 自动去掉的目录名前缀（正则）。留空即关闭 |
| `PORT` | `8080` | 容器内监听端口 |
| `DATA_DIR` | `/data` | 扫描结果与计划落盘位置 |

## 用法

界面是四步流水线，每步都要你手动点，**不会自动改任何东西**：

1. **扫描** —— 只读遍历目标目录，产出目录/文件统计和一级子目录表
2. **生成计划** —— 本地计算改名映射与清理清单，界面上可直接看到「原名 → 新名」样例
3. **执行改名** —— 真实修改文件名
4. **清理** —— 删除非图片文件与空目录

## 自动整理

容器默认**每 2 小时**自动跑一轮：

1. 扫描目标目录
2. 自动去掉目录名里的广告前缀（`PREFIX_STRIP`，默认 `^www[.]98T[.]la@`）
3. 生成改名计划，**自动执行改名**
4. 把待删的非图片文件与空目录**列在界面上**，但**不执行删除**

**为什么自动改名却不自动删除？** 改名是幂等的 —— 每个文件都会先判断它当前实际叫什么（原始名 / 旧位数名 / 已达标名），所以重复跑、中断重跑都不会出错。而删除不可逆：虽然 115 会把它送进回收站保留 30 天，但没有理由让一个定时任务替你做这个决定。

要真正删掉，打开 Web 界面点第 4 步的「删除非图片 + 空目录」。不想自动就按 `WATCH_INTERVAL=0` 启动，回到纯手动模式。

作业互斥：自动整理发现已有作业在跑时会跳过本轮，不会和你的手动操作打架。

## 界面上的设置

Web 界面底部有「设置」卡片，可直接修改下列项目。保存后**立即生效**并持久化到 `/data/settings.json`，容器重启也保留；界面设置优先于环境变量。

| 设置项 | 对应环境变量 | 说明 |
| --- | --- | --- |
| 目标目录 | `ROOT_PATH` | 要整理的目录 |
| 编号位数 | `PAD` | 4 → `0001.jpg` |
| 自动整理间隔 | `WATCH_INTERVAL` | 秒；`0` = 关闭自动 |
| 目录去前缀正则 | `PREFIX_STRIP` | 多个前缀用 `\|` 分隔；留空 = 关闭 |

**加多个前缀**：用 `|` 分隔即可

```
^www[.]98T[.]la@|^\[广告\]|^www\.[a-z0-9]+\.(com|net)@
```

保存时界面会**校验正则合法性**（写错直接报错、不会存进去），并告诉你当前匹配到多少个目录名。用 `[.]` 代替 `\.` 可以少一层转义烦恼。

**把间隔调短会不会触发风控？不会。** 因为 CD2 对 115 的 `maxQueriesPerSecond` 是硬闸门（默认 0.9），无论你把间隔设多短，CD2 都不会让请求超过这个速率——客户端这侧改不动它。

真正要留意的是**持续占用的比例**：一次完整扫描 112 个目录约需 129 秒，所以间隔一旦设到 2 分钟以内，就变成不间断扫描，把那份配额一直占满，还可能拖慢同时进行的改名。建议不低于 **15 分钟**；放新片频率不高的话，2 小时足够。

## 安全设计

- **改名是幂等的**：每个文件都会先判断它「现在实际叫什么」——原始名、旧的 3 位名或已达标的 4 位名，因此任务中断、改过编号位数、重复点击都能正确续跑，不会双重改名
- **删除走回收站**：115 不支持永久删除，删掉的文件进 115 回收站，30 天内可捞回
- **删目录前二次确认**：删空目录前会再列一次，发现已有内容就跳过
- **风控识别**：错误信息命中「频繁 / rate limit / throttle」等关键词会在界面高亮告警
- **令牌不落前端**：`/api/config` 只回 `hasToken: true/false`，从不回传令牌本身

## 已知限制

- 只处理 CD2 挂载的**云端**路径；本地路径不走这套逻辑
- 图片扩展名白名单见 `src/tidy.mjs` 的 `IMG_EXT`，需要更多格式自行添加
- 单次只跑一个作业，不支持并行多目录
